## 3. 实际遇到的问题与修正

### 3.1 首次上板失败：HPM0 位宽不匹配

首包 `f8_bundle_20260928_003336_214` 能加载 PL/DTBO/ZOCL，但原生服务报告 `F8 status ABI mismatch`。失败发生在 BO 分配及 GEMM 提交前，随后成功回退。
只读寄存器值 `FPD_SLCR.afi_fs=0xa00` 表明正在运行的 PS HPM0 为 128 bit，第一版 Vivado 平台配置为 32 bit。

修正为 HPM0=128 bit，重新综合、实现与封装；新增加载前只读位宽门槛和启动寄存器日志。最终 magic、ABI、两个构建 tag 都正确读回，后续真实计算通过。HP0 原本就是 128 bit，继续保持。
没有通过写 PS 配置或修改启动固件来规避不匹配。[失败日志](../results/c_integration/f8_bundle_20260928_003336_214/board_load_260053649355199.jsonl)、[服务错误](../results/c_integration/f8_bundle_20260928_003336_214/native_owner.log)、[实际位宽](../results/c_integration/f8_runtime_research/ps_widths_20260928.json)。

### 3.2 AXI 观测接线导致原接口端点悬空

Vivado 添加标量观测线时覆盖了 interface 成员连接，旧运行在综合警告后于 `opt_design` 报 `Opt 31-67`。
修复为 GEMM、SmartConnect、status 三端同时连接，并在生成时检查端点数和唯一驱动；综合遇到相关悬空警告即失败。
最终成功构建采用修正后的连接；旧失败运行不计入 PASS。

### 3.3 发布元数据与实际 burst RTL 不一致

原 `component.xml` 的三个 `HAS_BURST=0` 与发布 RTL 的 INCR burst 不符。
构建脚本只在隔离副本把三个值改为 1，原 ZIP 和原始 RTL 保持逐字节不变；变更前后哈希记录在构建清单。

### 3.4 SDK 和 xclbin 文件检查

实际 ARM SDK 的部分头文件位于 `experimental/`，需要使用实际安装路径并显式链接 libuuid。
不存在的 section 调用 `get_axlf_section()` 会抛异常；改为遍历 `get_axlf()`，严格允许六类元数据 section，拒绝 BITSTREAM/OVERLAY/PDI 等内容。
最终 native 编译/链接及 metadata 纯文件检查 PASS；[失败记录](../results/c_integration/f8_runtime_research/native_compile_final.txt)与[最终源码/程序哈希](../results/c_integration/f8_runtime_research/native_compile_startup_diagnostic_hashes.txt)均保留。

### 3.5 其他可靠性调整

构建 tag 由硬件输入指纹生成，Vivado 参数用可接受的十进制 wide 值。
Python RPC 使用总时限；超时丢弃连接以防旧响应串到下一请求。未证明完成/排空时保留 native BO/CU 所有权并拒绝重新提交。
可恢复的已完成任务经过 Continue、Idle、outstanding=0、quiet=1 后清除隔离状态。

## 4. 实际板上测试效果

测试环境：commercial K26 / KV260，Vivado 2020.2.2，Linux `6.8.0-1015-xilinx`，XRT/ZOCL 2.18，DFX manager `2024.2.0-0ubuntu1~xlnx1`。
板端墙上时钟当时不正确；阶段日期采用主机时间，原始板端日志保留 monotonic 标识。

| 项目 | 结果 | 解释 |
|---|---|---|
| 零值、单位矩阵、INT8 极值、非对称符号矩阵 | 每类连续两次，8/8 PASS | 独立整数 checker 对比每个输出 |
| 恢复后再次计算 | 1/1 PASS | 与上项合计 9 次 / 576 个元素 |
| 输入与缓存边界 | PASS | X/W 不被改写；Y 预置毒值；三 BO 尾部 guard；回读同步；旧返回结果不被后续运行覆盖 |
| 高地址 DDR | PASS | 三个实际 BO 的高 32 bit 非零，地址完整写入并用于 PL 访问 |
| AXI 完成状态 | PASS | 每次错误锁存及未完成事务为 0，CTRL=4、quiet=1 |
| 客户端断开 | PASS | 另一次真实提交后断开 socket，native PID=224571 保持，显式 RECOVER 后重用 |
| 正常停止与回退 | PASS | SAFE_STOP、exit=0、无设备使用者后恢复 starter；31 个包文件运行前后哈希一致 |

| BO | 实际设备地址 | 分配字节 / 有效字节 |
|---|---|---|
| X | `0x846f0c000` | 4096 / 64 |
| W | `0x845735000` | 4096 / 64 |
| Y | `0x846f11000` | 4096 / 256 |

每任务 X AR/R=64/128，W AR/R=512/512，Y AW/W/B=4/64/4。
观测点位于三个 32-bit GEMM master，数据拍对应 2816 B；这不是 HP0 128-bit 拍数，也不是物理 DDR 总流量。

客户端断开测试覆盖“已提交、未消费完成结果”的恢复；未证明断开瞬间 DMA 仍活动，也没有测试 SIGKILL 或永久 AXI 阻塞。
native 以 uid=1000 和临时 render 组执行，未永久修改 ubuntu 组。当前 starter / ZOCL 未加载 / XRT 0 devices 是回退后的已验证状态。

原始证据：[机器汇总](../results/c_integration/f8_bundle_20260928_012117_473/board_validation_summary.json)、[计算/恢复 JSONL](../results/c_integration/f8_bundle_20260928_012117_473/board_smoke_262414267686403.jsonl)、[加载/回退 JSONL](../results/c_integration/f8_bundle_20260928_012117_473/board_load_262414267686403.jsonl)、[native 日志](../results/c_integration/f8_bundle_20260928_012117_473/native_owner_262414267686403.log)。

## 6. 已知限制与后续范围

- 固定 `(M,K,N)=(8,8,8)`，无动态尺寸、补零、裁剪、tiling、INT4、稀疏或 D64/P2；无 PIPELINE/UNROLL 等新增计算优化。
- 永久 AXI 卡死时保留资源；硬件 reset/isolation 恢复未实现。外部强杀、内核崩溃、断电不在资源保证内。
- 仅有 BO 尾部 guard，没有前部 guard；本次实际分配均位于高 DDR，未强制低 DDR 对照。
- 内核存在无 IRQ、overlay property 内存泄漏提示与 `zyxclmm_drm` node refcount 告警；当前采用轮询。功能回退通过不等于内核无残留分配。
- 长期反复 overlay 切换、物理错误注入、独立封存验收和性能 benchmark 未运行。
- 原作者原始 HLS 构建报告缺失的问题不由本次平台报告补齐。

下一步可将本次冻结配对包交给独立验收人员；性能工作需先定义可分离 kernel/同步/调用开销的 benchmark。它们是待开展工作，本次提交不宣称完成。
