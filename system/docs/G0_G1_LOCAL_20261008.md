# 新电脑接手与 G0/G1 本机候选

接手基线为 `eba1a78ece0fe4eea7931c5a3458845cb6842bfd`，实际远端协作分支及 `team-handoff-20261007` 标签/Release 均仍是此提交，PR #2 为 OPEN/DRAFT，main 为 `cd0870d`。开发分支为 `codex/runtime-g0-g1-20261007`。采用父版仍是 `system_a3_20261005_02` 的 OPT35a/V2A；CF1、OPT38、B3 和新的 `v3` 都没有生产采用资格。

本次完成接手、G0 契约与可运行的 G1 私有对象/接收器/ledger/B 计时候选。**G1 整体仍为 PARTIAL：真实 Linux socket、记录、恢复和 C ABI/owner 尚未接入此核心；ARM 与板测 NOT RUN。** 没有给生产路径增加一个跳过检查的标记，也没有改变旧 CF1/父版源码或两次提交方式。新的适配边界见 [session.h](../board/model_backend/v3/session.h)，生产接线是明确的下一依赖，不能把普通 C++ callback 测试解释为实际 fsync、peer 或 CU 证明。

## G0 冻结边界

|边界|保留要求|当前实现/资格|
|---|---|---|
|外部 wire 字节|有界 prefix、严格 JSON、重复 key/解码 NUL/类型拒绝、身份/shape/全 body SHA|[Receiver](../board/model_backend/v3/frame.h) 每帧只解析一次，header 后立即 admission，body 后才交付 Frame|
|真实 peer|SO_PEERCRED、UID、PID/birth；重连重新检查|核心接收实际 ExecutionPeer；真实 Linux 观察尚未接线，不能由 header 自报替代|
|外部记录/文件|路径锚定、inode/type/UID/mode/link、真实 SUB/COMP 全读回、损坏封存|[Adapters](../board/model_backend/v3/session.h) 为强制接口；公开测试仅用普通内存适配器|
|W|真实注册文件检查、全部长度/SHA|每层私有读取后 Authority 对全部 W 再核验；未引入任务快照或文件缓存|
|CU/BO/AXI|唯一 owner、一次整层 start、Done latch、drain、guards/const/traffic、UNKNOWN 保留|继承语义解析验证完整 native；实际 kernel/checkpoint 适配及观察 NOT RUN|
|C ABI 借用内存|重叠拒绝、同步生命周期、X/W 事后不变、无自动 REQUEST 重试|旧 ABI3 实现未改；新的 C ABI 生产接线 NOT INTEGRATED|
|B 数值|RNE、[-127,127]、逐行 X scale、两次 FP32 乘后加 bias|新 B 插件与同机 CF1 完整 49 层图、logits 与 X/W/Y 摘要等价；没有数值协议修改|
|UI/collector|真实执行来源、request 身份、starts、不伪造 readiness|新离线 collector 只接 CPU_REFERENCE、0 starts，production_capability=false；生产代理/UI 仍未完成当前组合 Gate|

内部 Frame 的 header/body 为私有共享 const 所有权，外部 header 和 body 在 digest 回调之前一起深复制。Request/Result 的构造仅由 Authority 完成，不接受公共 validated 字段。Scope 拥有不可变 TrustedContext 与非回绕 generation；同一配置的两个 Authority 也不能交换凭据。作用域引用是持有生命周期的私有能力，**没有按借用指针地址查询的缓存**。请求匹配比较已拥有的 canonical request，内部 ledger/query/ACK/encode 不再序列化或摘要相同对象。跨入新 wire/文件边界仍重新严格核验。

Result 的终末 header 凭据保留到任务结束，Y 在正确 ACK 后从 ledger 释放；调用者已取得的共享 const Frame 可以继续安全持有 Y。重复 ACK 仍调用完整终末记录/native 读回适配器，并核对原 peer 与完整 confirmation，不能用释放后的 Y 指针做匹配。

核心单线程、一个 active/UNKNOWN/未 ACK 结果；所有会执行回调的状态操作防重入。默认最多 1024 个永久保留 ID，覆盖 20 图的 980 个 ID 加 44 个边界用例。每记录最多两个 16 KiB header 及两个不超过 16 KiB 的 canonical request，序列化文本上界 64 MiB；JSON/map 分配另有受记录数与严格 schema 限制的开销，实际峰值 **NOT MEASURED**。达到上界在新 admission 前拒绝，不能删除旧 ID 后重用。X≤151296 B、一个 pending Y≤605184 B；UNKNOWN 不释放 owner/BO。G2 如需更长任务，须先固定新的容量与生命周期合同。

## 状态与持久化顺序

|状态/操作|前置事实|成功后状态|失败处理|
|---|---|---|---|
|admission|严格 header、完整 task/ID/generation、真实 peer、start counter、空闲且无 pending|RECEIVING，ID 永久预留|重复/错身份不改变旧执行；容量拒绝 0 新 start|
|接收/准备|全部 X body SHA；真实 SUBMITTED 与 W 全核验|RECEIVING prepared|短帧/坏 SHA/准备失败→REJECTED_BEFORE_START，0 start|
|start intent|准备完成，唯一 start 路径|UNKNOWN_OR_QUARANTINED|从此不能再宣称未执行或重发 REQUEST|
|实际 start 观察|同 ID，实际 counter=before+1|EXECUTING|观察丢失→UNKNOWN，保留所有者|
|完成|实际一 start、Done/idle/drain、完整 native/guards/const/traffic、Y SHA|COMPLETED_UNACKED|native 写入/全读回失败→fault/UNKNOWN，保留 Y|
|ACK|原 request、Y digest、counter、真实完整 COMPLETED/native 读回|ACKED_Y_RELEASED|错 ACK/缺死亡与 sealed proof 保留 Y；记录损坏 faults owner|
|STOP|无 active/UNKNOWN/pending/fault，实际 CU/AXI quiet|SAFE_STOP|不可强杀或卸载|

正常生产时序仍是：B 准备→bridge **SUBMITTED append+fsync+完整读回**→REQUEST→owner admission/body/真实记录/W→checkpoint→一次 start→Done/drain/完整输出→native 写入并全读回→RESULT→bridge 核对文件/借用 const→**COMPLETED append+fsync+完整读回**→Y 消费→ACK→owner 再核对记录/native/实际状态→释放 pending→ACK_RESULT。提交次数仍是每层两次，49 层 98 次；此数来自未改的生产合同，不是本次实测。异常 QUERY/恢复、失败封存与更多 barriers 仍单独计入。

本机 Session 是 owner 适配接口，不创建生产记录、socket、BO 或 MMIO。公开测试中的 SUB/COMP callback 次序只证明核心拒绝缺失/损坏的外部事实，**不证明持久化或 Linux 文件检查**。真实适配必须逐项复用并绑定 CF1 的 `record_log.h`、storage/recovery/checkpoint；不能通过 callback 直接返回成功来跳过它们。

## G1 计时合同

[新 B 插件](../research/v3/custom_op/quant_linear_v3.cpp) 的相邻 wall/当前线程 CPU stamp 构成互斥分区：

|字段|边界|
|---|---|
|B_input|进入 ComputeV2 到输入/shape/W/scale 核验与私有 scratch 分配结束，含锁等待|
|B_quantize|仅动态逐行量化|
|B_prepare|backend/请求标识/ABI 包装、冷 bridge open；终点紧贴 run 调用|
|C_ABI|仅 bridge->run 调用；当前生产绑定关闭，**NOT EXERCISED**|
|B_CPU_REFERENCE|CPU 候选的整数 GEMM，与 C_ABI 分开标签|
|B_receipt|C 回执与 payload SHA 核验；同一 digest 用于随后 trace，不重复摘要|
|B_dequantize|输出获取与两次 FP32 乘后加 bias|
|B_trace_export|普通完整 trace 的组织与实际写入/close|
|B_dump_export|可选 Xq/sx/Y 证据导出|

`pre_terminal_export_wall_ns` 和 `thread_cpu_ns` 必须分别等于所有子项之和。写入这份 timing row 的自身成本无法递归写进同一 row，明确记为 `terminal_export_cost=ENCLOSING_SESSION_RUN`；外层 `session_run_including_terminal_export_ns` 包含实际终末导出，不能从端到端成本中删掉。旧 `gemm_api_us` 仅保留为宽边界历史字段，不用于新 C 成本归因。记录同步、host wait/core 等 C 内部分账尚未接线，不由 B 计时推算。

采样、摘要适配与终末写入都是诊断候选，净观察开销 NOT QUANTIFIED。Windows thread CPU 时钟分辨率可能导致短区间为 0；不能据此称无 CPU 成本。600 ms 整网剩余软件、C ABI 100 ms、B 回执/trace 30 ms 的 ARM 结构预算均 **NOT MEASURED**；不相加分位数，不拼接历史候选数值。
